       }

● services/transaction-service/app/main.py created. Key implementation
  decisions:

  - Route ordering — GET /transactions/fraud is declared before GET 
  /transactions/{transaction_id} so FastAPI doesn't match "fraud" as a path
  parameter.
  - Kafka — graceful degradation — _build_kafka_producer() runs in a thread
  (constructor makes a network call). If it throws, _kafka_producer stays None
  and _publish_transaction_event logs a warning and returns without failing the
  request.
  - Kafka shutdown — flush() is awaited via asyncio.to_thread to drain in-flight
  messages before close.
  - DynamoDB Decimals — amount and fraud_probability are stored as
  Decimal(str(...)) to satisfy boto3's number type; float() cast on read-back in
  _item_to_response.
  - status reserved word — DynamoDB's status is a reserved keyword; the PATCH
  UpdateExpression aliases it as #st.
  - ConditionalCheckFailedException — caught via botocore.exceptions.ClientError
  with error code check (the reliable boto3 pattern), returning 404 when the
  transaction doesn't exist.
  - Initial item — fraud_probability and model_version are omitted from the
  initial put_item (PENDING state); _item_to_response uses .get() so missing
  keys return None.

● Three files created. Key design decisions:

  Consumer loop — uses asyncio.to_thread(_consumer.poll, 1000) with a 1-second
  timeout so the event loop stays free between polls. CancelledError breaks the
  loop cleanly on shutdown; all other exceptions log and sleep 2s before
  retrying rather than crashing.

  Per-message safety — each _process_message call inside the loop is wrapped in
  its own try/except so a bad message never kills the consumer.

  build_inference_features — made async since it does Redis I/O (INCR, EXPIRE,
  SADD). Redis INCR returns a count that starts at 1 on first call; the EXPIRE
  is only set on that first call, which gives a true sliding window without
  resetting the TTL on every transaction.

  is_new_device — SADD returns the number of newly-added members (1=new,
  0=already seen), which maps directly to the flag. Device tracking has no
  explicit TTL per spec; easy to add later.

  Graceful Kafka degradation — both consumer and producer failures during
  startup are logged as warnings and execution continues. The /health endpoint
  surfaces kafka_consumer: "unavailable" and consumer_task: "stopped" so
  alerting can detect the degraded state without the service being down.

  Persistent httpx.AsyncClient — created once in lifespan and shared across all
  message processing, avoiding per-request connection overhead.
